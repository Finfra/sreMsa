# Java 설치

* Zipkin 에 로그를 보내는 예제를 빌드·실행하려면 Java 가 필요합니다.
* 실행 위치는 **`i1`(실습용 Console서버)** 입니다.
* 기준 버전은 **OpenJDK 17** 입니다.
    - cf) 예전 자료는 이 문서가 8, [2.zipkinTransactionTrace](../2.zipkinTransactionTrace/README.md) 가 11 을 깔도록 갈려 있었습니다. 같은 VM 에서 두 버전을 오가는 혼란을 없애기 위해 **17 하나로 통일**했습니다.

## 1. 설치 [i1에서 실행]

```
sudo apt-get update
sudo apt-get install -y openjdk-17-jdk-headless
```

* 확인 : 아래처럼 나오면 됩니다.
```
java -version
javac -version
```
```
openjdk version "17.0.20" 2026-07-21
OpenJDK Runtime Environment (build 17.0.20+8-1-24.04-Ubuntu)
OpenJDK 64-Bit Server VM (build 17.0.20+8-1-24.04-Ubuntu, mixed mode, sharing)
javac 17.0.20
```

* cf) `-jdk-` 를 깔면 `-jre-` 가 함께 들어옵니다. 실행만 할 거라도 컴파일이 필요한 실습이 뒤에 있으므로 **jdk 로 설치**합니다.

## 2. JAVA_HOME 설정 [i1에서 실행]

```
echo "JAVA_HOME=/usr/lib/jvm/java-17-openjdk-amd64" | sudo tee -a /etc/environment
export JAVA_HOME=/usr/lib/jvm/java-17-openjdk-amd64
```

* 위 두 줄은 하는 일이 다릅니다. 첫 줄은 **다음 접속부터** 적용되게 하고, 둘째 줄은 **지금 쓰는 창에** 바로 적용합니다.
* 확인 : 값이 비어 있지 않아야 합니다.
```
echo $JAVA_HOME
```

* **주의 : `~/.bashrc` 에 적는 방식은 쓰지 마십시오.**
    - Ubuntu 의 기본 `~/.bashrc` 는 맨 위에서 **대화형이 아닌 셸을 그냥 빠져나갑니다**(`case $- in *i*) ;; *) return;; esac`).
    - 그래서 사람이 직접 친 명령에서는 값이 보이지만, **`ssh i1 "명령"` 처럼 한 줄로 실행하거나 빌드 스크립트·Ansible 이 실행할 때는 `JAVA_HOME` 이 빈 값**이 됩니다.
    - Maven·Gradle 은 이 값을 보고 JDK 를 찾으므로, 그때 가서 원인 모를 실패가 납니다.
    - `/etc/environment` 는 로그인 과정에서 읽히기 때문에 위 경로 모두에서 값이 잡힙니다.
* cf) `java`·`javac` 실행 파일 자체는 `/usr/bin` 에 등록되므로 `PATH` 를 따로 손댈 필요가 없습니다.
* cf) 설치된 JDK 가 여럿일 때 기본값 확인·변경은 `update-alternatives --display java` / `sudo update-alternatives --config java`

## 3. Java Compile과 실행

* 실제로 컴파일이 되는지 한 번 확인하고 넘어갑니다.
* **주의 : 파일명과 클래스명이 같아야 합니다.** (`A.java` ↔ `public class A`)

```
cd ~
cat <<EOF> A.java
public class A {
  public static void main(String[] args) {
    System.out.println("hi from " + System.getProperty("java.version"));
  }
}
EOF

javac A.java
ls A.*
java A
```

* 확인 : 아래가 나오면 설치가 끝난 것입니다.
```
hi from 17.0.20
```

* 정리
```
rm -f ~/A.java ~/A.class
```

## 4. 여러개의 파일이 있는 복잡한 구조는?

* Maven : 기존 많이 사용.      - 복잡함
* Gradle : 요즘들어 많이 사용. - 간단함

* ⚠️ **주의 — 뒤따르는 빌드 실습(`2.MavenBuild.md`·`3.GradelBuild.md`)은 현재 예제 저장소 문제로 완주되지 않습니다.**
    - Gradle 예제는 빌드 설정이 **`jcenter.bintray.com`** 을 바라보는데, 이 저장소는 **2021년에 닫혔습니다.** JDK 버전과 무관하게 실패합니다.
    - Maven 예제는 `pom.xml` 의 source/target 이 **1.5** 로 지정돼 있어 JDK 17 이 거부합니다(`Source option 5 is no longer supported`).
    - 두 예제 모두 이 실습 저장소 **바깥**에 있어 여기서 고칠 수 없습니다. 복구는 별도로 진행 중입니다.
    - **Zipkin 본 실습(`1.zipkin_install` 이후)은 영향을 받지 않습니다.** 위 두 문서는 Java 빌드 도구를 소개하는 보조 자료입니다.
